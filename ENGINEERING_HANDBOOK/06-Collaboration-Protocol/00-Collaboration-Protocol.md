# Collaboration Protocol

## Purpose

The Collaboration Protocol protects continuity across sessions.

ClienteYA is not developed as a sequence of isolated conversations.  
It is developed as a continuous architecture.

Every new session must continue from the architecture, not from a blank page.

---

## Language Protocol

Conversations are conducted in Dutch.

Formal documents are written in English.

The ClienteYA application interface is fully Spanish in its first implementation.

Translation never replaces architectural thinking.

---

## Product Principle

ClienteYA is not a Spanish app.

ClienteYA is a global architecture with its first implementation in Spanish.

The app must always be built according to the architecture, identity, and scalability principles of ClienteYA.

---

## Global Architecture Principle

Global by Architecture.  
Local by Configuration.  
Spanish by First Implementation.

Local differences such as language, currency, date formats, communication habits, taxation, market behavior, and regulation must be handled through configuration whenever possible.

They must not be hardcoded into the core product logic.

---

## Working Method

Architecture before writing.

Discovery before design.

Identity above preference.

No implementation without architectural validation.

No document without Document Architecture.

No feature exists because it is interesting.

Every feature, document, or decision exists because the architecture has made it necessary.

---

## Session Start Rule

At the start of every new session, the first task is to identify:

1. The current architectural position.
2. The active phase.
3. The next logical step.
4. Whether the conversation is about architecture, manuscript, or implementation.

Only after this validation may work continue.

---

## Continuity Rule

The architecture is the source of continuity.

A new chat may interrupt context, but it must never interrupt the architecture.

The purpose of the Collaboration Protocol is to make the working method repeatable, stable, and scalable across sessions.

---

## ClienteYA Principle

We are not building a local tool.

We are building a global commercial operating architecture.

LatAm is the first implementation.

The Netherlands and other markets must remain possible without rebuilding the core product.

The product must therefore be designed so that expansion requires localization, not reinvention.
